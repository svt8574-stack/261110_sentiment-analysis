# 06 — 테스트, 보안 점검, Vercel 배포

## 테스트 전략
- 자동 테스트: Node 내장 `node:test`와 `assert`로 입력 검증, 결과 검증, 오류 매핑 등 순수 함수 테스트. AI/Supabase 호출은 모의 객체로 대체한다.
- 통합 테스트: 실제 `.env.local`을 사용하여 API→OpenAI→Supabase 동작을 확인한다. 비용이 발생할 수 있으므로 소수의 테스트만 실행한다.
- UI 수동 테스트: Chrome/모바일 뷰포트에서 기능·접근성 확인.
- 실제 API/DB 키가 없다면 통합 테스트는 **미실행**으로 표시한다. 성공했다고 쓰지 않는다.

## 배포 절차
1. Git 저장소를 만들고 `.env.local`, `node_modules`, `.vercel`이 제외됐는지 확인한다.
2. GitHub 저장소를 Vercel에 연결하거나 Vercel CLI로 배포한다.
3. 프레임워크 프리셋은 **Other**(정적 HTML + Functions)로 설정한다.
4. Vercel 프로젝트 Environment Variables에 `OPENAI_API_KEY`, `OPENAI_MODEL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 입력한다. Preview/Production 환경 적용 범위를 확인한다.
5. Supabase SQL Editor에서 `supabase/schema.sql`을 실행한다.
6. `npm run check` 후 Preview 배포에서 정상/오류/DB 저장을 확인한다.
7. Production으로 배포하고 배포 URL에서 같은 검증을 반복한다.
8. Vercel의 함수 로그와 OpenAI 사용량/비용을 확인한다.

## 배포 시 흔한 문제
- 화면은 뜨지만 API 404: `api/analyze.js` 위치, 프로젝트 루트, 리라이트를 확인한다.
- API 503: 환경변수 설정·적용 환경·재배포 여부를 확인한다.
- AI 502: 모델 접근 권한, SDK 호출 형식, API 사용량, 타임아웃을 확인한다.
- DB 저장 실패: URL/키, 테이블 생성 여부, 서비스 역할 권한을 확인한다.
- CSS/JS 404: `index.html`의 `/public/...` 경로가 배포 환경과 일치하는지 확인한다.
